# ADR 0006: Continuous integration and published images

- **Status:** Accepted
- **Date:** 2026-10-19

## Context

Sodalis had no CI. Quality gates (`pnpm test`, `pnpm typecheck`, `pnpm build`)
ran only locally, and the root test script listed its script tests by hand, so
one was silently left out. Every developer built the Compose images locally.
On a MacBook this is slow: the API image compiles FFmpeg, and Parakeet TDT
downloads about 670 MB of weights. Code is mostly written by AI agents, which
respond reliably to a failing check but drift from prose-only conventions.
Data must never reach a cloud provider without per-run consent.

## Decision

- **GitHub Actions on GitHub-hosted runners.**
  - `ci.yml` runs on pull requests.
  - `publish-images.yml` runs the same CI as a reusable workflow on `main` and
    `v*` tags, then publishes images.
  - `codeql.yml` scans JavaScript/TypeScript, Python, and the workflows
    themselves.
  - The single required check is `ci-ok`.
- **Node gates on Linux and macOS (Apple Silicon).** FFmpeg is installed on
  Linux so the transcoder and speech-http tests run. Python tests run with the
  standard library's `unittest`. Compose configuration is rendered for both
  published and locally built images. Workflows are linted with actionlint,
  and dependency review blocks high-severity vulnerabilities.
- **Test tiers.** All deterministic tests block merges; they take about 30 s
  in total.
  - **Tier 1:** security, privacy, and public-API tests: the desktop host
    boundary, assistant actions, memory consent and deletion, Home safety,
    server APIs, stack selection, and speech-http limits.
  - **Tier 2:** avatar and desktop UX tests.
  - **Tier 3:** evaluation and benchmark tooling. Its tests are kept while
    cheap, but new benchmark code needs none.
  - **Tier 4:** live cloud tests. They never run in CI, and no provider
    secrets are configured.
- **Quality tooling, phase 1.**
  - Stricter `tsc` flags (`noUnusedLocals`, `noUnusedParameters`,
    `noImplicitReturns`, `noFallthroughCasesInSwitch`).
  - CodeQL, dependency review, actionlint, and Dependabot.
  - A formatter, a minimal lint set, and dead-code detection (Biome and knip)
    follow in a separate change, so the one-time reformat stays isolated
    (task 0055).
  - We don't adopt a full ESLint/Prettier setup or coverage thresholds. On the
    current code, Biome's recommended lint rules reported about 300 findings,
    277 of them non-null assertions and few real defects. Agents also tend to
    game coverage thresholds.
- **Published images.** `ghcr.io/tno/sodalis-{api,gateway,parakeet-tdt}` are
  built natively for amd64 and arm64.
  - Tags: `main`, `sha-<short>`, and on releases `X.Y.Z`, `X.Y`, and `latest`.
  - Each image gets build provenance attestations and OCI licence labels.
    Licence labels cover the bundled assets: the CC BY-NC avatar in `gateway`,
    and the CC BY 4.0 Parakeet weights in `parakeet-tdt`, with attribution.
  - Per-architecture registry build caches (`:buildcache-<arch>`) are
    published as well.
  - Optional evaluation engines (Whisper, Whistle, Piper, Fish Speech) are not
    published.
- **Compose pulls Parakeet TDT** (`SODALIS_IMAGE_TAG`, default `main`).
  `SODALIS_LOCAL_IMAGES=true` builds it locally instead. The API and gateway
  images still build locally so code changes take effect, but they reuse the
  registry build cache and fetch dependencies in a separate layer.

## Consequences

- Pull requests get a single pass/fail signal, and agents get actionable
  failures.
- Mac developers no longer download the Parakeet weights or compile FFmpeg on
  first start.
- The GHCR packages must be public for anonymous pulls, which is an
  organization setting. Publishing `gateway` redistributes a non-commercial
  avatar with its notice.
- A change to the Parakeet Dockerfile only takes effect locally with
  `SODALIS_LOCAL_IMAGES=true`, or after it merges to `main`.
- The vendored Aster browser suite still runs manually when the snapshot is
  refreshed.
